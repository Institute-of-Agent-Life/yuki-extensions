### 卡片用法

所有路徑與命令均為**預定新增**，若先前卡已建立同一路徑則為修改；除非卡上明列退役，**不刪舊項目檔案或資料**。每張卡的 `tests/cases/<ID>.py` 是可執行的案例，持有本卡的 fixtures/故障排程/斷言；跨倉只讀 core 發布的 golden，不複製一套業務規則。`ci/check.py` 在本倉第一個提交建立，介面為 `python ci/check.py <ID> --out <dir>`：解析本倉 lock，建本卡涉及的真程式，調用對應 case；Rust 用鎖定依賴，Python 用鎖定環境，活動資料使用獨立暫存目錄。失敗也寫 manifest、退出碼與斷點。行為提交按 K00：先寫卡上時序並證明可攔住故障，再實作；成功和指定負例都通過才交同一個 commit。bootstrap 卡先用 stdlib 建自測，不依賴未建好的產品。

每次命令執行前依 manifest 備好唯讀套件快取與 baseline bundle；執行期禁止外網與付費。需實際平台/機器的附加證據分 `verified / failed / not_run(reason)`；不得用 skip 清掉應做的離線斷言。`--out` 要用新的 attempt 目錄，以下 `01` 為首輪示例；真資料不上傳公開 CI。實際 branch/SHA、平台、工具版本、依賴 digest、seed/時鐘、每端收件、DB 前後差、費用來源都記在產物 manifest。命令最後同時檢查本卡新增的 schema/SQL/SDK、編譯及相鄰既有行為，與業務無關的全量套件留 release matrix。

**並行合併。** 先決列只登記限制開工的直接交付；另需讀取但已由其前置帶入的原件單列；階段、同倉目錄和章號不是排隊號。相同插件的模組使用同一公開 manifest：先合者建立最小 manifest，後合者重基加差異、再驗該包；不要複製第二個插件。候選測試包含多個面時，釘一個同時具備它們的宿主 digest，不把分別通過的兩版當成聯測。
